SMART E-LEARNING PLATFORM — FULL PROJECT EXPLANATION
======================================================
This file explains, from the beginning to the end, how this project works,
what you built yourself, and what was completed/corrected on top of it.
Nothing in your file names, folder names, component names, or styling (CSS)
was changed. Only the JavaScript logic inside files was completed or fixed,
plus a small amount of new CSS was ADDED (never replacing your existing
rules) for the one new piece of UI (the signup program picker).


PART 1: THE BIG PICTURE
======================================================
This app is an e-learning dashboard, styled after the "Smart" design
(purple/indigo, sidebar on the left, main content on the right). A logged-in
user sees their own personalized Dashboard, Lessons, Schedule, Materials,
and Assessments — built from a small set of fake "database" files instead
of a real backend.

The core idea running through every single page is the same 3-step chain
you already understood clearly during our conversations:

  1. Who is logged in?              -> AuthContext gives you `user`
  2. Which programs did they pick?  -> filter enrollments by user.id
  3. What belongs to those programs? -> filter lessons/materials/assessments
                                         by those program/lesson ids

Every page in this project (Dashboard, Lessons, Materials, Schedule,
Assessments) repeats this exact chain. Once you're comfortable with it in
one file, you're comfortable with it everywhere.


PART 2: THE DATA FILES (your fake database)
======================================================
Location: src/data/

users.js
  Holds the fake people (Grace, Samuel, and you — Ayanfe Scope). Each user

  know who owns what.

      safely ignore or delete it whenever you like.
    - `lessons` (named export): the REAL, active lessons data. Each lesson

lessonMaterials.js
  Files (PDFs etc.) attached to individual lessons, connected via lessonId.

userAssessment.js
  Each user's due date / score / status for a specific lesson, connected

  for one lesson — unlike lessons themselves, which are shared).

teachers.js
  Teachers linked directly to a userId (a simpler, direct relationship,
  since this data doesn't need to travel through programs).

calendar.js
  Calendar/task events tied directly to a userId.

forum.js
  Left empty/unused, exactly as agreed — Forum was intentionally left for
  a future session.

components/data/user.js
  This is a small leftover file from earlier in the project. It is NOT

PART 3: AUTHENTICATION — Context/AuthContext.js
======================================================
This is the "brain" of who's logged in, and now also handles signup.

What it holds:
  - user      -> the currently logged-in person (or null)
  - error     -> a message to show when login/signup fails
  - allUsers  -> ALL users, starting as a copy of your users.js file, but
                 kept in React state (useState) so new signups can be added
                 to it while the app is running
  - enrollments -> ALL enrollment records, same idea — starts as a copy of
                 your enrollment.js file, but lives in state so new signups
                 can add their own enrollment lines

login(email, password)
  Unchanged from what you built — searches allUsers for a match, sets
  `user` on success, sets an error message on failure.

signup(formData, selectedProgramIds)  <-- THIS IS NEW
  This is what makes your "pick courses during signup" idea actually work:
    1. Checks the email isn't already taken (using .some(), a cousin of
       .find() that just returns true/false instead of the actual match)
    2. Checks at least one program was selected
    3. Works out a brand-new unique id for the new user by taking the
       highest existing id and adding 1: Math.max(...allUsers.map(u => u.id)) + 1
    4. Builds the new user object and adds it to allUsers
    5. Builds one enrollment object per selected program (same shape as
       your existing enrollment.js entries) and adds them to enrollments
    6. Logs the new user in immediately (setUser)

IMPORTANT — why enrollments now live in Context instead of being imported
directly from data/enrollment.js in every page:
  Before, Dashboard/Lessons/Materials/Assessments each did:
      import enrollments from "../../data/enrollment";
  That only ever reads the ORIGINAL file, frozen in time. If a new user
  signed up, their enrollment lines would never show up anywhere, because
  every page was reading the old, unchanging file instead of the live,
  in-memory list. Now, every page instead does:
      const { user, enrollments } = useContext(AuthContext);
  So they always see the current, up-to-date list — including brand new
  signups — without needing to touch the original data file at all.

PART 6: THE ARRAY METHODS USED THROUGHOUT (quick reference)
======================================================
.filter()  -> keeps items that pass a yes/no test. Result can be smaller
              than the original list, or the same size, but never bigger.
              Used everywhere to narrow down "all X" into "just this
              user's X".

.map()     -> transforms every item into something else. Result is always
              the same length as the original. Used both to reshape data
              (e.g. pulling just programId out of an enrollment) AND to
              turn data into actual JSX elements on screen.

.find()    -> returns the FIRST single item that matches, or undefined if
              none match. Used whenever we want exactly one related item
              (one assessment for this lesson, one program for this
              lesson), not a list of them.

.some()    -> new in this pass, used once in signup() to check "does any
              user already have this email?" It works like .find(), but
              instead of giving you the matching item, it just gives you
              true or false.

.includes()-> asks "is this specific value inside this list?" Used to
              check whether a lesson's programId is one of the ids this
              user is enrolled in.
